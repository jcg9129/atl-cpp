# `atl::int128` and `atl::uint128`

128-bit integers for hosted C++23 with 8-bit bytes and exact 32-bit and 64-bit
unsigned integers. The aliases select native integers when `ATL_HAS_INT128` is
true and structural software classes otherwise. The software classes are always
available as `atl::detail::software_int128` and `atl::detail::software_uint128`.

\include int128/arithmetic.cpp

## API

The aliases come with `<atl/types/alias.hpp>`, which compiles the software
classes only when they are the aliases. Include `<atl/types/int128.hpp>` to use
the concrete software classes on any target, and `<atl/types/int128_format.hpp>`
to `std::format` the aliases everywhere (native integers are formatted by the
standard library; the formatters of the software classes themselves are in
`<atl/types/detail/software_int128_format.hpp>`). Both classes
have public `std::uint64_t low, high` members, in that order, with natural
alignment. They are trivially copyable, standard layout, and structural types
usable as non-type template arguments. Default initialization leaves the limbs
uninitialized; value initialization (`Integer{}`) produces zero.

| operation | software semantics |
|---|---|
| `Integer(value)` | Implicit from built-in integers and bool; explicit from floating types, truncating toward zero |
| `Integer(low_word, high_word)` | Construct directly from two unsigned words |
| Signed to unsigned | Implicit, preserving the two's-complement pattern |
| Unsigned to signed | Explicit, preserving the two's-complement pattern |
| `static_cast<Builtin>(value)` | Explicit integer conversion keeps low bits modulo the destination width; bool tests both words |
| `static_cast<Floating>(value)` | Round the magnitude to nearest, ties to even, then apply the sign; double-double formats round a high component and its exact residual separately |
| `+ - * / %`, unary `+ -` | Usual arithmetic conversions; signed division truncates toward zero; remainder has the dividend's sign |
| `+= -= *= /= %= &= \|= ^= <<= >>=` | Compute in the operator's result type, convert back, return a reference |
| `++ --` | Prefix returns a reference, postfix returns the previous value |
| `~ & \| ^` | Two's-complement bits; binary operators use the usual arithmetic conversions |
| `<< >>` | Result has the promoted left operand's type; signed right shift is arithmetic |
| `== != < <= > >=` | Compare in the arithmetic common type |
| `<=>` | `std::strong_ordering`; available only without narrowing signed/unsigned conversions and without bool operands |
| `!`, explicit `operator bool()` | Zero test and nonzero test; built-in short-circuit `&&` and `\|\|` remain available |

Mixed operators accept every built-in integer spelling, including bool and the
character types, and the other software class. Character types follow their
promotions. Enums and floating operands do not participate. An unsigned rank-128
operand makes the arithmetic result unsigned; otherwise it is signed rank 128.
For example `software_int128 + uint64` is signed, while
`software_int128 + software_uint128` is unsigned. A built-in left operand of a
shift retains its promoted built-in type (`1 << software_uint128{3}` is `int`).

`std::numeric_limits` supplies all members (127/128 value bits, 38 decimal digits,
`is_modulo == true` for both). `std::hash` consumes both limbs even on targets
with a narrow `size_t`. `std::common_type` is symmetric with supported integer
operands. These specializations name the concrete classes, so native aliases
retain their normal behavior. Standard type traits are not specialized;
`atl::integral`, `atl::traits::make_signed_t`, and `make_unsigned_t` recognize the
software types. `widen_mul_type_t` widens 64-bit integers to the selected 128-bit
type. The formatting header supplies decimal output for the concrete software
classes, including when native aliases are selected.

The optional formatter supports `b/B/o/d/x/X`, sign (`+/-/space`), `#`, literal
or dynamic width (including zero), a single Unicode scalar as fill, `< > ^`
alignment, and zero padding. With no explicit alignment, zeros follow the sign
and radix prefix. Parsing is constexpr.
Floating presentation, precision, character presentation, and locale formatting
are not supported.

## Complexity

Storage is two words. Addition, subtraction, multiplication, comparisons,
bitwise operations and shifts take constant time. Division by a word uses at
most two corrected base-2³² quotient digits after an initial word division.
Division by a larger divisor uses one bounded word division and at most one
quotient correction. Floating conversions inspect at most 128 bits. Formatting
uses bounded storage and a bounded number of digit operations. No integer operation allocates.

## Preconditions

Asserted with `ATL_ASSERT`:

- Division and remainder require a nonzero divisor; signed minimum divided by
  minus one is invalid for both `/` and `%`.
- Shift counts must be nonnegative and smaller than the promoted left operand's
  bit width (128 for either software class). Counts are checked before narrowing.
- Floating input must be finite and its truncated value must be representable.
  Unsigned conversion accepts values between -1 and 0 because they truncate to 0.

Software signed overflow wraps through unsigned limb arithmetic. Native signed
overflow retains the built-in language rules. Invalid operations with assertions
disabled are outside the API contract.

`ATL_NO_INT128` and `ATL_FORCE_FALLBACKS` **must match across translation units**: they change the aliases,
template instantiations, and ABI. `ATL_PORTABLE_WIDE_ARITHMETIC` forces the
portable primitive bodies for testing, retaining native aliases when available.
`ATL_FORCE_FALLBACKS` selects both software aliases and portable primitive bodies.
All configuration switches must match across translation units, including the
primitive-backend switch: they affect inline definitions. They leave the
concrete software representation unchanged. All published
types and utilities, including the 256-bit accumulator, hashes and radix sort,
work with either backend.

## Measured performance

**128-bit arithmetic.** `benchmarks/types/int128.cpp` is a cost
table, not a race: it times the software `uint128` against native `__uint128_t`
(add, multiply, 128/64 and 128/128 division, multiply-high) and the 64-bit word
primitives they are built from (64x64 multiply, add with carry, subtract with
borrow, word-quotient and general 128/64 division).
Software 128/128 division takes
0.047/0.028 ms versus native 0.027/0.017 ms per benchmark batch; the native integer row compiled with native flags varies between runs (1.72x spread), so this row
alone does not establish a stable ratio.

**256-bit product comparison.** `benchmarks/types/int256.cpp` races two
implementations of `detail::compare_products` (the exact sign of `a*b - c*d`
for signed 128-bit operands). The library multiplies the two's-complement bits
as unsigned values, corrects the high half by masks and subtracts the products,
with no negation and no branch on the signs. "By sign magnitude" multiplies the
absolute values, negates the product when the signs differ and forms the
difference as `x + (-y)`. The benchmark compares 10⁶ independent quadruples of
random mixed-sign operands of about 100 bits, so it measures throughput.

AMD EPYC-Milan (Hetzner ccx23, 4 dedicated vCPU), x86-64 Linux,
GCC 15.2.0, RelWithDebInfo, assertions off, 2026-11-25.
Flags: `-O2 -g -DNDEBUG -std=c++23` (plain),
`-march=native -O2 -g -DNDEBUG -std=c++23` (native).
Minimum of the per-run means, milliseconds; 5 runs of 25 samples per row.

| flags | library | by sign magnitude |
|---|---:|---:|
| `-O2` | 27.4 | 30.1 |
| `-O2 -march=native` | 27.8 | 28 |

The library is faster with both flag sets: sign magnitude takes
(30.1/27.4 - 1) = 9.85% longer plain and (28/27.8 - 1) = 0.72%
longer native.

## Pitfalls and notes

A class cannot reproduce every built-in integer property:

- Built-in integral promotions and overload ranking cannot be reproduced by
  conversion operators. Use explicit casts at interfaces that need built-ins.
- `switch`, subscripts, and pointer arithmetic require a cast to a built-in type.
  Software classes cannot be bit-fields or enum underlying types.
- `std::integral`, standard integer type traits, `<bit>`, `std::gcd`, and
  `std::from_chars` do not recognize these classes. The library does not specialize
  forbidden standard traits. Use the optional formatter for decimal output.
- Atomics follow the general trivially-copyable class rules; neither lock freedom
  nor built-in atomic integer operations are promised.
- List-initialization cannot issue built-in narrowing diagnostics through integer
  constructors. Explicit output conversions deliberately keep low bits.
- A plain `const` class variable is not a constant expression; use `constexpr`.
- The software classes have class ABI, which can differ from native `__int128`
  calling conventions and alignment.

## How it works

The primitive layer uses four 32×32 products and explicit carries for 64×64
multiplication. Two full-word additions retain the 0, 1, or 2 middle carry for
the high half of 128×128 multiplication.

For bounded 128/64 division, shift the divisor so its top bit is set and apply
the same shift to the dividend. At each of two base-2³² digits, divide the top
two dividend digits by the leading divisor digit. This is an upper estimate of
the quotient digit. Compare the estimate's product with the second divisor
digit against the partial remainder and next dividend digit, decrementing when
necessary. Normalization bounds correction to two decrements. Once corrected,
the remainder fits in a word; modular unsigned subtraction recovers it exactly.
Undo normalization after the second digit. General 128/64 division first divides
the high word and passes its remainder to the bounded step.

For a divisor with a nonzero high limb the quotient fits one word. Dividing
the halved dividend by the normalized top divisor word yields an estimate;
scaling and decrementing it gives a lower bound within one of the exact quotient.
A product subtraction and at most one correction recover the quotient and
remainder. Every intermediate uses unsigned limbs. Signed division converts limb
patterns to unsigned magnitudes, performs the same division, then restores the
quotient and remainder signs without built-in signed overflow.

Portable bodies are used during constant evaluation. At runtime, native unsigned
128-bit arithmetic or supported MSVC intrinsics accelerate the word primitives
unless `ATL_PORTABLE_WIDE_ARITHMETIC` or `ATL_FORCE_FALLBACKS` is defined.
MSVC x64 uses `_umul128`, `_addcarry_u64`, `_subborrow_u64` and `_udiv128`;
MSVC ARM64 uses `__umulh`; MSVC x86 uses the portable bodies. Floating output
extracts and rounds a single significand before scaling by powers of two for IEEE formats,
avoiding double rounding from separately converted limbs. IBM double-double
`long double` instead rounds the high binary64 component, computes its exact
residual with limb arithmetic, and rounds that residual into the low component
before summing them. Implementation is derived from positional arithmetic and
C++23 conversion rules, without imported division code.
